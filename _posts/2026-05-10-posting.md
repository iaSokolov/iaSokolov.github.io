# Jekyll без боли: Как правильно вести посты в статическом блоге

Jekyll — это классика для тех, кто любит полный контроль, скорость и Markdown. Но если не настроить процесс правильно, ведение блога может превратиться в рутину с файлами и путями. 

В этой статье разберем, как организовать работу так, чтобы создание контента оставалось творчеством, а не администрированием.

## 1. Структура — это фундамент
По умолчанию Jekyll ищет посты в папке `_posts`. Когда постов становится много, найти нужный файл — тот еще квест.

**Совет:** Используйте подпапки по годам или категориям внутри `_posts`:
```text
_posts/
  2024/
    2024-05-10-my-travel.md
  2023/
    2023-12-01-jekyll-tips.md
```
Jekyll отлично индексирует вложенные папки, а вам будет проще ориентироваться в архивах.

## 2. Идеальный Front Matter
Front Matter — это блок настроек в начале файла. Чтобы не копировать его каждый раз вручную, создайте себе шаблон (boilerplate).

Минимальный набор для удобства:
*   `layout: post` — какой шаблон оформления использовать.
*   `title` — заголовок статьи.
*   `date` — дата (важна для корректной сортировки).
*   `categories` и `tags` — для автоматической навигации.
*   `description` — для SEO и красивых превью в соцсетях.

## 3. Работа с изображениями
Главная «боль» статических сайтов — относительные пути. 

*   **Плохо:** Сваливать сотни картинок в одну общую папку `images/`.
*   **Хорошо:** Создавать структуру `assets/img/posts/ГГГГ-ММ-ДД-название-поста/`.

Чтобы ссылки не бились при переносе сайта на другой домен, всегда используйте фильтр `relative_url`:
```markdown
![Превью]({{"/assets/img/posts/2024-05-10/hero.jpg" | relative_url }})
```

## 4. Как ускорить процесс?

### Используйте черновики (Drafts)
Не обязательно сразу публиковать пост. Храните идеи и «недописы» в папке `_drafts`. Чтобы увидеть их на локальном сервере, запустите его с флагом:
```bash
bundle exec jekyll serve --drafts
```

### Автоматизация через плагины
Если ваш хостинг позволяет использовать кастомные плагины (например, если вы деплоите через Netlify или Vercel), попробуйте:
*   **jekyll-admin**: дает удобный UI в браузере для написания и редактирования постов.
*   **jekyll-seo-tag**: автоматически генерирует все мета-теги (OpenGraph, Twitter Cards).

## 5. Выбор редактора
Jekyll — это про текст. Поэтому важно, в чем вы его пишете. 
*   **Typora**: идеальный минималистичный Markdown-редактор с Live Preview.
*   **Obsidian**: если вы ведете базу знаний и хотите превращать заметки в посты.
*   **VS Code + расширение "Jekyll Snippets"**: для тех, кто не хочет выходить из привычной среды разработки.

## 6. Группировка по категориям
Если ваш блог растет, стандартная папка `_posts` превращается в свалку. Jekyll позволяет группировать файлы по папкам-категориям.

**Вариант А: Порядок в архиве**
Просто создайте папки внутри `_posts/`. Это не изменит ваши URL, но поможет быстро находить нужные исходники:
`_posts/tutorials/2024-01-01-post.md`

**Вариант Б: Категории в URL**
Если вы хотите, чтобы структура сайта отражала категории (например, `://site.com`), вынесите `_posts` во вложенные директории:
`/dev/_posts/2024-01-01-post.md`
`/design/_posts/2024-01-01-post.md`

В этом случае Jekyll автоматически назначит категорию посту исходя из названия родительской папки.


## Итог
Чистота в папках, продуманный Front Matter и правильный выбор инструментов делают Jekyll невероятно мощным и приятным движком. Настройте свой workflow один раз, и вы больше никогда не захотите возвращаться к тяжелым CMS.
